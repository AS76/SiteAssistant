The **task** is the unit of work on site. Every task belongs to a site, has a distinct **executor** and **reviewer**, and only moves through allowed transitions. The golden rule: **whoever executes cannot review their own work**.

## Create a task

What it is for: putting work on site with someone who executes it and someone who verifies it.

1. Open **Tasks** and press **New task**.
2. Fill in title, area and company.
3. Choose **executor** and **reviewer**: they must be two different people.
4. Choose the **type** — **Ordinary** or **Corrective** — the **priority** and, if needed, the **due date**.
5. Press **Save**: the task starts in status `todo` and appears in the **To do** column.

| Field | Required | Notes |
| :-- | :-- | :-- |
| Title | Yes | At most 180 characters |
| Area | No | At most 100 characters |
| Company | No | At most 100 characters |
| Executor | Yes | The person doing the work |
| Reviewer | Yes | The person who checks and closes the work |
| Type | No | **Ordinary** (default) or **Corrective** |
| Priority | Yes | `normal`, `high`, `urgent` |
| Due date | No | Date, pre-filled with today |

**The executor and the reviewer must be two different people**: the application rejects the assignment if they coincide.

:::caution[If the task is not created]
- **Executor and reviewer are the same person:** choose two different people; the rule applies to owners too.
- **Required fields empty:** the form shows the error above the buttons and moves focus to the first field to fix.
- **Task created but not visible:** check the board filters and the selected site.
:::

## Ordinary and corrective tasks

The **type** tells planned work apart from work that fixes something:

- **Ordinary**: the planned work. It is the default and it is not stored as a type, so tasks created before this classification stay ordinary.
- **Corrective**: work that fixes a defect or a non-conformity. The board cards show a **Corrective** badge.

The type is chosen at creation and cannot be changed afterwards: tasks are not editable. The **Type** filter in the filter bar applies to the board, to the list and to the CSV export, which has a **Type** column with the translated label.

## The statuses

| Status | Meaning |
| :-- | :-- |
| `todo` | To do: planned, not started yet |
| `in_progress` | In progress |
| `to_verify` | Reported done, awaiting review |
| `closed` | Verified and closed |
| `blocked` | Stopped by an impediment |

## Move a task forward

What it is for: recording the status change with the person, the time and the note that justify it.

1. Open the task detail from the card or the row.
2. Look at the **current status** and the available buttons: they change with the status.
3. Press the button for the move you need — for example **Start**, **Submit for review**, **Block**.
4. Write the **note** or **reason** the move requires.
5. Press **Save**: the **history** in the detail records who, when, from which status and with which note.

| From | To | What you do | What it requires |
| :-- | :-- | :-- | :-- |
| `todo` | `in_progress` | **Start** | — |
| `todo` | `blocked` | **Block** | A reason |
| `in_progress` | `to_verify` | **Submit for review** | An execution note |
| `in_progress` | `blocked` | **Block** | A reason |
| `to_verify` | `closed` | **Verify** | A note; only the designated reviewer or an owner |
| `to_verify` | `blocked` | **Block** | A reason |
| `closed` | `in_progress` | **Reopen** | A reason; only the designated reviewer or an owner |

:::caution[If the move is not available]
- **No buttons in the detail:** the current status does not allow that move. Reopen the detail to refresh the data.
- **Missing note or reason:** the form rejects the save and points to the field.
- **Verification denied:** only the designated reviewer or an owner can close or reopen; whoever executed the work cannot verify it.
- **Blocked task:** resuming from `blocked` is not exposed in the interface in this version.
:::

## The review

Closing requires two distinct acts:

1. the **executor** reports completion with an execution note;
2. the **reviewer** confirms with their own note.

Only the designated reviewer (or an owner) can close or reopen. Whoever executed the work can never verify it themselves.

## Attachments

In a task detail you can attach photos or PDFs, up to **15 MiB** per file; uploading is reserved to owners and editors. The verification evidence remains a **text note**: the attachment does not replace the note.

## Saved views

What it is for: getting back in one click the filters, sorting and columns you use every day.

1. Open **Tasks**: above the filters you find **Saved view**, with the entry **No view**.
2. Set the filters and choose **Board** or **List**; in the list also set **Sort by**, **Direction** and the **Visible columns**.
3. Press **Save as view**, give it a name (at most 80 characters) and, if you want, select **Share with site members**.
4. Pick the view from the menu to apply it again; the selection applies to the current site.
5. After a change, **Modified · not saved** appears next to the menu: press **Update to current state** to save the new filters, or **Rename** or **Delete view**.

Views are **personal** by default; a **shared** view is visible to every member of the site and is marked with **· Shared**. Only the person who created the view or a site owner can change or delete it: for everyone else a shared view is read-only.

:::caution[If a view does not do what you expect]
- **Name already used:** names must be unique for the same site and the same person; choose another one.
- **Read-only view:** it is shared and you did not create it. To change it, save your own copy with **Save as view**.
- **View no longer available:** it was deleted or you switched site. Reload the page and choose **No view** again.
- **The columns do not change:** sorting and columns are set in **List** mode; the board uses the saved filters but has no columns to choose.
:::

## What is not available yet

- Sharing a view with individual people instead of the whole site.
- Editing a task after creation.
- Acceptance criteria, long descriptions, checklists.
- Deleting a task.
- Rejecting a submission or resuming a blocked task from the interface: those transitions exist only via API and are not yet exposed in the application.
