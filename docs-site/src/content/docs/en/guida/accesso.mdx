You sign in to SiteAssistant with your **email** and **password**. There is no public registration: accounts are created in two ways, both designed for people working on site.

## Sign in

What it is for: opening a session on the site you need to work on.

1. Open the application address in your browser, on desktop or mobile.
2. If there is no active session, the **Sign in** form appears.
3. Enter your **email** and **password**, then press **Sign in**. The **◉** button next to the password field shows the password you typed; press it again to hide it.
4. After signing in you only see the sites you belong to, and you can choose your working context from the menu at the top.

The email is case-insensitive: `Mario.Rossi@example.com` and `mario.rossi@example.com` are the same account.

:::caution[If sign-in fails]
- The error message never reveals whether the email or the password is wrong.
- After **10 failed attempts** in the same **15-minute** window (for the same email and network address), sign-in is suspended for a while: wait a few minutes and try again.
- If the session expires or is revoked, the application takes you back to the sign-in form.
:::

## If you do not have an account yet

What it is for: getting an account when you do not have one, without public registration.

From the sign-in form you can press **Request access**:

1. Enter your email.
2. The request reaches whoever administers the application, who can **approve** or **reject** it.
3. If approved, you receive a **temporary password** by email.
4. On first sign-in the application asks you to **change the password**.

A request does not create the account on its own: it needs an administrator's approval. The review link the administrator receives expires after **72 hours** and can be used once: if it has expired, the request must be sent again.

:::caution[If the request does not arrive]
The request stays pending: it does not create the account until an administrator approves it. If the approval email does not arrive, ask the administrator to check the request and send it again only if it has expired.
:::

## Forgotten or temporary password

- **Forgot password:** from the sign-in form press **Forgot password** and enter your email. If the account exists, you receive a new temporary password by email.
- **Change password:** if you are using a temporary password, a notice appears with the **Change password** button. It requires your current password and a new one, different and at least **12 characters** long. Other sessions are closed. You can dismiss the notice with **×**; it stays hidden for the browser session.

If the email service is not active, these operations are unavailable: the application tells you and asks you to try again later.

Access requests, resets and password changes are rate-limited: after **10 attempts** in the same **15-minute** window the operation is suspended for a few minutes.

## How long the session lasts

- The session lasts **7 days** and is remembered by the browser with a secure cookie.
- The **Sign out** button closes the session on the server immediately.
- Closing the browser without signing out does **not** close the session: it stays valid until it expires or you sign out.

:::note[Expired session]
If the session expires or is revoked, the application takes you back to the sign-in form.
:::
