SiteAssistant is organised into **views** that share the same context: the **selected site**. Change the site, and every view shows that site's data.

## The header

The header contains, from left to right:

- the **site selector**, which lists only the sites where you have a role;
- the **navigation** between views, grouped on desktop in three sections: **Operations** (Overview, Tasks, Deviations, Diary), **Site** (Site progress, Time bookings, Project structure, Cost impacts) and **Management** (Sites, [Tools](../../moduli/attrezzature/), [Fitness](../../moduli/idoneita/));
- the gear for [Settings](../impostazioni/) (currency, decimals, separators);
- the link to the manual;
- the **language selector** (IT / EN);
- your name and the **Sign out** button.

The **AI** button at the bottom right opens the [data assistant](../assistente-ai/).

## The navigation groups

On desktop the side navigation shows a heading per group: **Operations** for daily work, **Site** for progress and cost data, **Management** for sites, tools and fitness. The entries are the same as before; only the order they are collected in changes. On a phone the bottom bar does not use the groups and is described in the [Mobile quick guide](../mobile/).

If an owner has excluded a module from your access, its entry does not appear in the navigation and a direct link to the view shows **Module unavailable**. Module access is described in [Users and roles](../../amministrazione/utenti-e-ruoli/#module-access).

## Reading the Overview

What it is for: seeing in seconds what is stuck, what is waiting for a review and what is overdue on the selected site.

1. Choose the site from the **selector at the top**.
2. If you want to see only some blocks, press **Customize** and choose which ones to show and in what order: the choice is personal and applies to the selected site.
3. Read the four operational and financial indicators: **Open deviations**, **Booked hours**, **Open claims**, **Settled**.
4. Read the four task counters: **To execute**, **To verify**, **Closed**, **Overdue**.
5. Scroll the three charts: **Deviations by status**, **Progress by section**, **Hours per week**, and the **Earned value** panel.
6. Finish with **Keep an eye on** and **The site at a glance**: tasks ordered by urgency and the summary of verified closures.

The four indicators count:

- **Open deviations**: deviations not closed and not rejected;
- **Booked hours**: sum of the hours recorded on work days;
- **Open claims**: claimed amount of claims not closed;
- **Settled**: sum of the settlement amounts recorded on claims.

Below the charts, the **Earned value** panel shows EV, PV and AC in hours, with CPI and SPI, calculated from the planned hours of the items and the booked hours. If the site has no planned hours, the panel says so instead of showing figures. See [Site progress](../../moduli/avanzamento/#planned-hours).

**Customize** opens the list of the eleven available blocks: the four indicators and seven panels (Deviations by status, Progress by section, Hours per week, Earned value, Keep an eye on, The site at a glance, Today's diary). Tick or untick them, move them with the arrows and save. The four indicators stay at the top; the panels follow the chosen order. **Restore defaults** puts every block back in its original order. A block without data keeps its empty state instead of disappearing, and if the layout cannot be loaded the page shows the defaults.

Owners and editors also find **Import planning export** here: the upload is described in [Import a planning export](../../amministrazione/import-pianificazione/).

:::caution[If the Overview does not load]
- If the indicators show **“API request failed”**, the server did not answer: check the connection and reload the page.
- If the counters stay at zero, check that you selected the right site: every view shows only the selected site.
- Charts appear only when the site data contains enough deviations, sections and weeks; a section without data shows a message, not an empty chart.
:::

## Tasks: board and list

What it is for: finding the task to move today and seeing where it stands in the flow.

1. Open **Tasks** from the navigation.
2. Choose **Board** for the columns by status, or **List** for the rows with priority, due date and people.
3. Use the filters: free text, **status**, **executor**, **priority**, **type**.
4. Open a card or a row for the detail, the available transitions and the history.

On narrow screens the board becomes a **status accordion**: you see one group at a time and open it with a tap, with no horizontal scrolling. This applies to the **Tasks** and **Deviations** boards. The filters apply to both the board and the list, and to the CSV export. Filters, sorting and list columns can be saved as a **view**: see [Tasks and reviews](../../moduli/attivita/#saved-views).

:::caution[If you cannot find a task]
- Check the active filters: a status or executor filter can hide the task you are looking for. The **Clear filters** button appears when the result is empty.
- Tasks belong to the selected site: change site from the selector at the top.
- If you have just created the task and cannot see it, reload the page: the board shows the data of the last load.
:::

## Sorting and filtering a table

What it is for: ordering rows and narrowing the list without exporting anything.

1. Open a view with a table: **Deviations** in **List** mode, **Site progress**, **Time bookings**, **Cost impacts**, **Tools** or **Fitness**.
2. Click a column header: the first click sorts ascending, the second descending.
3. From the keyboard, move focus to the header with Tab and press **Enter** or **Space**.
4. Press **Column filters**: a row of fields appears above the table, one per column.
5. Type in a field to filter that column. Clear the field to remove the filter, or press **Hide filters** to close the row.

<Shot
  src="/images/2026-11/en/impacts-desktop.png"

Sorting and filtering work on the rendered table, not on the stored data: they change nothing on the server.

:::caution[If sorting or filtering does not respond]
- On phones the **Column filters** button does not open the field row and headers are not visible: tables become cards and you filter with the menus above the table (status, priority, day, result).
- If a column does not sort, check that you clicked the header and not the row title.
- Column filters stay active while the page is open; reloading turns them off.
- If the list is empty after a filter, clear the fields one by one: filters add up.
:::

## Language

The IT/EN selector translates the interface labels immediately. The content you enter — titles, notes, reasons, diary entries — stays in the language you wrote it in. The chosen language and the selected site are kept in memory until the page is reloaded.

## Exports and printing

- **Task CSV:** exports the tasks you are currently viewing with the active filters, not the whole archive.
- **Report CSV:** the **Site report** view exports its two tables, progress and deviations, with dedicated buttons. See [Site progress](../../moduli/avanzamento/#site-report).
- **Print diary:** uses the browser's print dialog; there is no server-generated PDF.
- **Report PDF:** from the **Overview** or **Site progress**, the **Print PDF** button opens the report and the browser print dialog; here too the browser produces the PDF. See [Site progress](../../moduli/avanzamento/#site-report).

## Accessibility and devices

The interface is responsive and keyboard-navigable. The input forms are modal windows with focus management; validation errors are announced in the form's message area.

On phones navigation moves to a **bottom bar**: the full description is in the [Mobile quick guide](../mobile/).
